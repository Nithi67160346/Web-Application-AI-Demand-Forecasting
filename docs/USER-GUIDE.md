# คู่มือใช้งาน Demandly

## เปิดระบบ

Windows: เปิด `start-local.cmd` (ครั้งแรกใช้ `setup-local.cmd`). ใช้ Node.js >=22.13.0 และ Python >=3.10.
URL ที่ใช้จริงแสดงใน launcher; ถ้าพอร์ตเดิมไม่ว่าง ระบบจะเลือกพอร์ตถัดไป.
โหมด Docker ใช้ `setup.cmd` และ `start-web.cmd` เมื่อ Docker Desktop พร้อม.
สมัครบัญชีผ่าน Register แล้ว Login. บัญชีใหม่เริ่มด้วยพื้นที่ทำงานว่าง.
ปิดด้วย `stop-local.cmd` หรือ `stop-web.cmd` ตามโหมดที่เปิด. ข้อมูลยังเก็บไว้.

## นำเข้าข้อมูลของคุณเอง

1. เปิดเมนู **ข้อมูลบริษัท** แล้วกด **เลือกไฟล์จากเครื่อง** หรือลากไฟล์ลงกล่อง.
2. รองรับ CSV UTF-8 และ Excel `.xlsx` แผ่นแรก; สูงสุด 20 MB / 250,000 แถว.
3. **ดาวน์โหลด Template** จะได้ CSV ที่มีเฉพาะชื่อคอลัมน์ สำหรับใส่ข้อมูลของคุณเอง.
4. ตรวจ Preview: จำนวนรายการและตัวอย่างแถวมาจากไฟล์ที่เลือกจริง.
5. จับคู่ Date, Product, Region, Sales quantity และ Inventory. Inventory เว้นได้.
6. กดตรวจ Data quality. ต้องแก้แถวผิดทั้งหมดก่อนบันทึก. รายการที่เหมือนกันทุกค่าต้องยืนยันให้เก็บ.
7. เลือก **เพิ่มข้อมูลในชุดเดิม** หรือ **แทนที่ยอดขายเดิมทั้งหมดของพื้นที่ทำงาน**.
8. กด **บันทึกข้อมูล**. ก่อนกดบันทึก ไฟล์ยังไม่ถูกนำไปใช้เป็นยอดขายสำหรับ Forecast.

ระบบไม่เติมชุดข้อมูลให้บัญชีใหม่อัตโนมัติ และหน้าเว็บไม่มีปุ่มเลือก dataset ที่เตรียมไว้.
คอลัมน์มาตรฐาน: `sale_date,product_code,region,sales_quantity,inventory`.
Sales quantity และ Inventory ต้องเป็นจำนวนเต็มไม่ติดลบ. Date ใช้ `YYYY-MM-DD` ได้.
Inventory เป็น snapshot ณ วันที่ระบุ: ระบบใช้รายการล่าสุดของแต่ละสินค้า/พื้นที่ ไม่รวมค่าซ้ำทุกธุรกรรม.

## ใช้งานจากหน้าจอเดิม

ทุกเมนูใช้ฐานข้อมูลโดยตรง ไม่มีปุ่มสลับมุมมองตัวอย่างกับเครื่องมือฐานข้อมูล.

- **Dashboard**: จำนวนรายการ ยอดขาย กราฟ สัดส่วนตามพื้นที่ และแจ้งเตือนอ่านจากข้อมูลที่บันทึก.
  Forecast demand ระบุสินค้า/พื้นที่/ระยะเวลาของรอบล่าสุด ไม่ใช่ยอดรวมทุกสินค้า.
- **Forecast**: เลือกสินค้า พื้นที่ และ 7–180 วัน; ปุ่ม 1/3/6 เดือนใช้ 30/90/180 วัน.
  วันที่ต้นกำเนิดเว้นว่างเพื่อใช้วันล่าสุดของข้อมูล หรือกำหนดวันที่เพื่อวิเคราะห์ย้อนหลัง.
  ต้องมีอย่างน้อย 112 วันปฏิทินและ 56 วันที่มีรายการ. วันขาดหายต้องยืนยันให้เติมศูนย์.
- **Products**: ค้นหา กรอง ดูประวัติยอดขายและ snapshot ตามพื้นที่ แก้ชื่อ Lead time และ Safety stock.
  ค่าที่แก้ใช้กับการสร้าง Forecast และ Alert รอบถัดไป.
- **Alerts**: เปิดรายละเอียด เลือกสถานะ ใส่เหตุผล และบันทึก. ระบบเก็บผู้ทบทวนกับวันเวลา.
- **Monitoring**: นำเข้ายอดขายวันที่อยู่ในช่วงพยากรณ์เพื่อวัด Live metrics.
  ไม่มี Actual ใหม่จะแสดงรอข้อมูล. การแทนที่ยอดขายทั้งหมดจะไม่เทียบ Forecast เดิมกับชุดใหม่.
- **Settings**: บันทึกชื่อพื้นที่ทำงาน เกณฑ์แจ้งเตือน รีเฟรชทุก 15 นาที และตารางกระชับ.
  Owner เพิ่มบัญชีที่สมัครไว้แล้วเป็นสมาชิกทีมได้. Viewer อ่านอย่างเดียว; Planner ทำข้อมูลและ Forecast;
  Admin จัดการข้อมูลและการตั้งค่า. เลือกพื้นที่ทำงานจาก Sidebar เพื่อสลับทีม.
- **Account security**: เปลี่ยนรหัสผ่านแล้ว session เดิมทั้งหมดใช้ไม่ได้ ต้องเข้าสู่ระบบใหม่.

CSV export ดาวน์โหลดข้อมูลจริง. หน้า Data แสดงเวลาค้นหาและ PostgreSQL query plan.
การทดลองก่อน/หลัง index พร้อมต้นทุน INSERT อยู่ใน `indexing-lab/README.md`.

## วิธีประเมิน Forecast

เลือก last value, weekday mean, linear trend หรือ annual seasonal จาก validation ย้อนหลังสองช่วง.
ใช้ holdout 28 วันท้ายประเมินแยกจากข้อมูลที่ใช้เลือกโมเดล.
MAE คือความคลาดเคลื่อนเฉลี่ยต่อวัน; WAPE คือผลรวม absolute error / ผลรวม Actual.
WAPE ไม่มีค่าเมื่อ Actual รวมเป็นศูนย์. ไม่มีการตั้งค่า accuracy/confidence ขึ้นมาเอง.
กราฟที่รวมหลายวันแสดงค่าเฉลี่ยต่อวัน เพื่อไม่ให้ช่วงท้ายที่มีวันไม่ครบดูเหมือนยอดขายลดลง.
ช่วงความไม่แน่นอนใช้ความคลาดเคลื่อนย้อนหลังและขยายตามระยะเวลา ไม่รับประกัน coverage ในอนาคต.
หน้าเว็บใช้ยอดขายที่นำเข้าเป็นแหล่งข้อมูล; ไม่เพิ่มยอดจาก disease/policy/population แบบกำหนดเปอร์เซ็นต์เอง.

## ขอบเขตและดูแลระบบ

การแจ้งเตือนและ Review บันทึกในแอป; การผลิตจริงและการเติมสินค้าต้องดำเนินการผ่านกระบวนการของทีม.
ยังไม่มีการเชื่อม ERP, Email หรือข้อมูลภายนอกอัตโนมัติในหน้าใช้งาน.
ไฟล์ใน `datasets/` ที่ใช้ทดสอบก่อนหน้านี้เป็นข้อมูลสังเคราะห์และยังเก็บไว้สำหรับงานทดสอบ/วิชา indexing;
ผลทดสอบเหล่านั้นไม่ใช้รับรองความแม่นยำกับข้อมูลธุรกิจของคุณ.
Local PostgreSQL รับ connection เฉพาะ loopback และใช้ trust สำหรับเครื่องเดียว.
ก่อนเปิดให้เครื่องอื่นใช้งาน ให้อ่าน `docs/OPERATIONS.md` และใช้ production profile พร้อมรหัสผ่านและ TLS.
อย่าลบ `.cache/local-db` หรือ Docker database volume ถ้าต้องการเก็บข้อมูลเดิม.
